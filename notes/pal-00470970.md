# PAL packing function: reconstruction and remaining byte mismatch

`func_00470970` is a 32-byte function at main-image address `0x00470970`
on SCES_532.85. This is a research draft, not an additional matching function.
It is excluded from `src/`, the build, mapping tables and progress counts.

The [candidate](../research/ps2recomp-pal/drafts/func_00470970.c) writes this
64-bit value at object offset `0x38`:

```c
(high << 32) | low | (byte1 << 8) | (byte2 << 16)
```

The shifts and ORs use unsigned 64-bit values; no byte masks are inserted.
The original also leaves that value in `v0`. The draft models this observed
register value with a `u64` return type. This does not establish whether the
original source declared a return value or whether callers depended on one.

Six direct JAL sites were found in the main image: `0046E068`, `0046E3C0`,
`0047F62C`, `004F3FE8`, `004F400C`, and `004F6BB8`. Three overwrite `v0`
before using it; the other three return without changing it. These observations
do not settle the source-level return prototype. Indirect calls and callers of
those wrappers have not been exhaustively resolved.

## Remaining difference

With the unchanged compiler pipeline and the file-wide `-O1` option, the draft
is also 32 bytes long. Exactly one byte differs, in the instruction at function
offset `0xC`: the two source operands of an OR are exchanged. Its destination
and the other seven instructions are identical. There are no relocations.

This improves the earlier research draft, but is still not a byte-exact match.
Alternative OR groupings and term orders, narrower argument representations,
an inline helper, and instruction scheduling/register-move options did not
produce an exact match in this investigation. No register bindings, inline assembly,
compiler-output changes, or weakened match rules were used.

## Reproduce the comparison

From the repository root, with the documented toolchain and Python dependencies:

```sh
bash tools/cc.sh research/ps2recomp-pal/drafts/func_00470970.c build/pal-00470970.o -O1
python research/ps2recomp-pal/verify_00470970.py baserom/pal/main.elf build/pal-00470970.o --report build/pal-00470970-proof.json
```

The [checker](../research/ps2recomp-pal/verify_00470970.py) reads both supplied
ELFs without executing them. It verifies the size, lack of relocations, the
single differing byte and the exchanged operands. It then models the logical
shifts, ORs, return and store with exact symbolic bit origins. For every input
bit pattern, the lower 64 bits of all GPRs, the ordered store and return target
are equal. A changed shift fails equivalence, and an instruction outside the
admitted subset is rejected. This is not a sampling test.

[Recorded evidence](../research/ps2recomp-pal/packing-evidence.json) includes
the source and input-file hashes. The checker does not model the upper 64 bits
of 128-bit GPRs, prove the original C prototype, or test whole-game behavior.
It does not relax the project's byte-exact matching requirement. Issue #73
therefore remains open for this function and the unverified translation work.
